# /pr-follow-through

PR을 "만들고 끝"이 아니라 "머지 가능한 상태"까지 끌고 가는 스킬.

CI를 기다리고, 봇/사람이 남긴 리뷰 코멘트를 하나씩 코드와 대조해서 검증하고,
유효한 지적은 고쳐서 푸시한 뒤 resolve, 무효한 지적은 근거를 대서 반박한 뒤 resolve 한다.
새 코멘트가 붙으면 이 루프를 반복한다.

## 사용법

```
/pr-follow-through                          # 현재 브랜치의 PR
/pr-follow-through 123                      # PR 번호
/pr-follow-through https://github.com/o/r/pull/123
```

PR을 만든 직후, PR 브랜치에 푸시한 직후, 또는 "CI 통과할 때까지 봐줘"라고
할 때 자동으로 트리거된다.

## 요구사항

- [`gh`](https://cli.github.com) CLI 설치 + `gh auth login` 완료
- Python 3.8+
- 리뷰 스레드를 resolve 하려면 해당 저장소에 write 권한 필요

## 워크플로우

```
PR 확인 → 감사 스크립트 실행 → 스레드별 판정 → (수정·푸시) → CI 대기 → 재감사 → 반복
```

감사 스크립트는 `gh pr checks` + GraphQL `reviewThreads`를 함께 조회한다.
GitHub의 top-level 코멘트 API만 보면 **인라인 리뷰 스레드가 통째로 누락되기 때문에**
이 스크립트를 거치는 것이 워크플로의 필수 단계다.

```bash
python3 skills/pr-follow-through/scripts/pr_watch.py OWNER REPO PR_NUMBER
```

출력: 체크 상태 요약 + 실패/대기 중인 체크 목록 + 미해결 활성 스레드(경로·작성자·본문·URL).
종료 코드는 문제가 남아 있으면 1, 다 깨끗하면 0이라 루프 조건으로 쓸 수 있다.

## 판정 기준

리뷰 코멘트는 **주장이지 사실이 아니다.** 리뷰어의 확신도, severity 라벨, 봇 출력은 근거가 아니다.
현재 코드에서 실제로 도달 가능한 실행 경로가 있을 때만 유효로 친다.

| 판정 | 행동 |
|---|---|
| 유효 | 코드 수정 → 테스트 → 푸시 → **푸시 이후에** resolve |
| 무효 | 코드 그대로. `file:line`·런타임 동작·테스트 출력로 반박 후 resolve |
| 불명확 | 빠진 가정을 질문으로 남기고 스레드 열어둠 |
| 유효하나 범위 밖 | 후속 작업을 제안하고 열어둠 (승인 없이 PR 범위 확장 금지) |

stale/outdated 스레드도 같은 규칙을 적용한다 — 우려가 사라졌음을 확인하고 근거를 남긴 뒤 resolve.

## 안전장치

- 이 스킬 호출은 워크플로에 필요한 **리뷰 스레드 답글·resolve만** 승인한다. 무관한 PR 코멘트는 달지 않는다.
- 범위 밖 수정은 사용자 승인 없이 하지 않는다.
- 무관한 생성물/데이터 파일을 스테이징하지 않는다.
- self-hosted 러너 부재로 CI가 큐에 걸린 경우, 코드 실패가 아니라 인프라 대기로 보고한다.

## 종료 리포트

유효-수정 / 무효-반박 / 의도적 미해결 건수와 테스트·CI 증거를 요약하고,
열어둔 스레드는 ID와 사유를 명시한다.
